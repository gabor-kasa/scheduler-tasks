## TL;DR

Healthier than its "personal script" label suggests — it's a real deployed app with a genuinely good GitHub resilience layer (circuit breaker + rate limiter + bounded backoff in `github.ts`), explicit (non-wildcard) CORS, SSM-backed secrets, and CI that actually typechecks + tests + lint-builds on every PR and gates deploy on tests. The single most important finding is a **live within-team data leak**: the daily-standup route `await`s a *synchronous* permission function, so `!result` is always false and the "filter to your own activity" branch is dead code — every read-access user sees every teammate's activity (`daily-standup.routes.ts:104`). Close behind: **two private Google Calendar ICS URLs with embedded secret tokens are committed to git** (`storage-dynamodb.ts:79,94` — flag for rotation), and the **EventBridge cron Lambdas have no DLQ/onFailure**, so a morning where Jira/GitHub is down means the standup/stale-PR/dependabot jobs silently just don't run. A recurring theme is "wrong-but-green" results — partial Jira fetch failures, a mis-pathed lock condition, and an un-paginated DynamoDB scan all let the tool report success on incomplete data. No active compromise found; no real API credentials in git history (only a public `pk_test_` Clerk key). Cost not assessed (out of scope). Routing: the committed ICS tokens (#2) go to Balázs Antal (TechOps) / `#sekurity-korner` for rotation.

## Architecture notes

**What it is.** A deployed full-stack "Jira Analytics Dashboard" at `jiradashboard.kasa.dev`, not a script. Stack: React 19 / Vite / MUI v7 SPA on a CloudFront StaticSite; Express 5 backend running as a single proxy Lambda behind API Gateway v2; a Step Functions pipeline (InitializeJob → ListSprints → ProcessChunks[Map, concurrency 5] → ExportToSheets → GenerateSummaries → CompleteJob) of 6 worker Lambdas for async sprint processing; DynamoDB single-table (PK/SK + ttl); SST v3 (Pulumi) IaC.

**Scheduled automation (EventBridge):** daily standup reports (hsp 08:50, rc 14:50 weekdays), stale-PR checker (08/12/16 weekdays, **live mode** for hsp), safe-to-merge-dependabot DM (13:00 weekdays). Several mutate Slack/GitHub.

**Integrations:** Jira (`jira-client`), GitHub (`@octokit` App auth), Slack (`@slack/web-api`), GitClear, Google Sheets (`googleapis`), Anthropic SDK. Secrets via SSM Parameter Store with env-var fallback (`backend/lib/secrets.ts`) — clean, no hardcoded creds.

**Kasa-ecosystem note (resourcefulness):** standalone by design — does not consume Kasa shared service libs (`api-client`, `nest-common`, `queue-patterns`, `lambda-utils`, `logger`). It hand-rolls Jira/GitHub/sprint logic that overlaps the `shared-kasa-jira` and `shared-kasa-review-sprint` Claude skills (see Findings). Deployed in `us-west-2` like Kasa services but to the personal `gabor-kasa` GitHub + a `jiradashboard.kasa.dev` domain.

**Bus factor (Step 2.6):** single author by design — Gabor 342 commits, andrew-kasa 8, dependabot 16 (369 total since 2023-06-16, ~48k LOC). Bus factor = 1 everywhere; acceptable for personal tooling but means zero review on the automation that DMs the whole team and merges dependabot PRs.
