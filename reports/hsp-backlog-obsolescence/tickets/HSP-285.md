# HSP-285: CSS CodeAudit should handle custom codes with codeId references

- **Verdict:** not implemented
- **Label:** backlog-review-not-implemented
- **Confidence:** high
- **Checked:** 2026-10-15, by hand (pilot ticket 2)
- **Jira before write:** created 2022-12-05, updated 2023-10-02, parent KC-3833

## Claim

If this ticket were done, code audit would match custom ('CU') codes on locks to CSS code entities and
remove the ones CSS marks as removed. It would also not push `not_set` custom codes that have no code jobs.

## Evidence

- `css-api` @ origin/master `fcf1d70`, `service/src/processes/worker/handlers/code-audit/code-matcher.ts:7`
  and `:58`: callers must filter out 'CU' codes before matching. `getCodeTypeByCodeOnLockType` throws on 'CU' by design.
- `code-setting-service` (legacy), `functions/internal/code-audit/unit-code-synchronizer.ts:434-453`:
  custom codes are collected only to send a TechOps alert when a unit exceeds 10 of them. They are never matched or removed.

## Note for review

The figures in the ticket (about 580 removed custom codes, about 560 `not_set`) are from 2022. Re-measure
them before deciding whether this is still worth doing.
