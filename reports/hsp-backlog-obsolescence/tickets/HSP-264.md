# HSP-264: do not merge accounts using 3rd party booking emails

- **Verdict:** not implemented (an OTA-email guard exists in guest-api, but the merge in the ticket's examples is Kustomer's, and that has no email guard)
- **Label:** backlog-review-not-implemented
- **Confidence:** medium-high
- **Checked:** 2026-10-16, scheduled-task batch
- **Jira before write:** created 2023-09-23, updated 2024-08-10, no labels, no repository field, no parent, status To Do. Blocks HELP-171 (Open), duplicates linked from HELP-1538 and HELP-1559 (both Duplicate). One comment (Brandon Payne, 2023-11-29) with an example merged Kustomer profile.

## Claim

If this ticket were done, a guest or Kustomer profile would not be merged on a generic third-party email: tripactions.com,
narvan.com, m.expediapartnercentral.com, guest.booking.com, contactcfs.com, nespat.net, goglobal.travel, ebgsolutions.com,
customerservice@mytravel.support. The merge code would skip those emails.

## Evidence

- Kustomer side, where the ticket's example lives (`kustomer-sync` @ origin/master `f0b54f0`):
  - `utils/sendReservationsToKustomer.ts:248-250` always adds the guest's email as a merge search field.
  - `libs/kustomer/customer-merges/customer-merges-v4.ts:171` fetches a customer per field and `:135`, `:107` merge them. The only
    guard is for shared phones (`shouldCreateNewCustomerOnPhoneNumberMatch`, added by "limit shared phones", `f079e91`, 2026-02-04, #745).
  - `libs/kustomer/customer-merges/utils.ts:9` `IGNORED_EMAILS = ['@mchat.booking.com', 'noreply@expedia.com']` only strips those
    two from the stored email list (applied at `customer-merges-v4.ts:489`). It does not stop a merge on them, and none of the
    ticket's domains are in it. `CHANNEL_EMAIL_PATTERN` (`utils.ts:14`) only sorts channel emails to the end.
- Guest side (`guest-api` @ `657ccab4`): `service/src/utils/email-utils.ts:2-24` has `OTADomainList` and `isOTAEmail`. It
  contains guest.booking.com, m.expediapartnercentral.com, tripactions.com and mytravel.support, but not contactcfs.com, narvan.com,
  nespat.net, goglobal.travel or ebgsolutions.com. It blocks OTA emails from account setup
  (`components/auth/account-setup/account-setup.service.ts:88`, `:268`) and from the group-admin merge
  (`components/management/guest/guest.subscribers.ts:57`). The list predates the ticket (`c7210832`, 2023-03-20, EXT-2904).
- A grep of the HSP repos for narvan, nespat, goglobal, ebgsolutions and contactcfs found no hits outside ai_service notebooks and guest-api test files.
