# HSP-480: Prevent BU codes to exist without being assigned to a reservation

- **Verdict:** partial (backup-code half built in the new UI, expiry half not built anywhere)
- **Label:** backlog-review-unclear
- **Confidence:** medium
- **Checked:** 2026-10-16, scheduled-task batch
- **Jira before write:** Story, created 2023-11-14, updated 2026-09-24, no labels, no repository field, parent KC-3833, no sprint, status To Do. No links. One comment (Gabor, 2023-11-14: "require either a reservation or an expiry date, so the code gets removed at some point").

## Claim

If this ticket were done, the Kontrol code-add form would (1) force a confirmation code, and assign the new code to that reservation, when the
type is guest backup, and (2) offer an optional "Expires on" date for housekeeping and maintenance codes and show it in the "deleted at" column.
Alternative that would make it moot: backup codes can no longer exist unassigned for another reason. I did not find one.

## Evidence

- `kontrol-ui` @ `ea34ed10`, `libs/kontrol-ui/pages/access-codes/src/lib/components/create-code-dialog.tsx:366-372`: the "Confirmation Code" input is
  `required` when the type is backup. `handleSubmit` creates the code, then calls `assignCodeToReservation` with that confirmation code.
  Commit `15770e1fd`, 2026-08-12, HSP-3945 "require a reservation on manual backup code creation" (#2935). Part 1 is done in the new page.
- `css-api` @ `1ccf63d8`, `service/src/processes/app/router/codes/codes.validators.ts:91-97`: `createManualCodeRequestSchema` takes `code`, `comment`,
  `unitId`, `codeType`, `codeService` and nothing else. The API does not enforce the reservation (the UI does, in two calls) and has no expiry field.
- Expiry (part 2): no "Expires on" input in `create-code-dialog.tsx` (form values are `unitIds, codeService, codeType, code, comment, confirmationCode`),
  and a search for `expires on|expiresAt|expiryDate` across `kontrol`, `kontrol-ui`, `css-api`, `code-setting-service`, `kontrol-api` found
  only the old "Deleted at" column in `kontrol` `SmartLockCodes.vue:17`.
- `kontrol` @ `cbf3f48d`, `src/views/door-codes/SmartLockCodes.vue:198-204`: the old Vue page still calls `createManualCode` with no confirmation code,
  so a BU code can still be created unassigned there. Assignment stays a separate "assign to rez" action (`:225`).
