# HSP-578: Allow usage of archived Contentful entries for checkout page

- **Verdict:** unclear (the hiding part was solved another way; the manual-checkout part is a product question)
- **Label:** backlog-review-unclear
- **Confidence:** medium
- **Checked:** 2026-10-15, by hand (pilot ticket 3)
- **Jira before write:** created 2023-01-25, updated 2024-05-22, blocks HELP-165 (open)

## Claim

If this ticket were done, the Contentful Property type would have `isListedOnWebsite`, `standardCheckoutEnabled`
and `manualCheckoutEnabled`. A property could then be hidden from the website while manual checkout stayed possible.

## Evidence

- None of the three field names appear in any HSP repo on origin/master.
- Hiding is done another way: `isListed` on the Property and RoomType DB models.
  `guest-api` @ origin/master `59277576`:
  - `service/src/components/properties/properties.service.ts:53`: an unlisted property returns `PROPERTY_NOT_LISTED`.
  - `service/src/components/availability/availability.service.ts:58`, `:213`: availability requires `isListed: true`.
  - `service/src/components/booking/booking.service.ts:101-103`: booking requires `isListed: true`.
- Checkout content is read from Sanity or Contentful (`checkout.apartment-repository.ts:159-173`). Contentful still
  fails when it has no entry.

## Note for review

Hiding a property from the website is solved. Under `isListed: false`, booking is also blocked, so the
"hidden but manually bookable" case (the MBS story) is not covered. Is that case still needed? If not, close as Obsolete.
