# HSP-930: Proxy segment to avoid adblockers

- **Verdict:** unclear (Segment is still not proxied; PostHog now runs through our own domain alongside it)
- **Label:** backlog-review-unclear
- **Confidence:** medium
- **Checked:** 2026-10-19, scheduled-task batch
- **Jira before write:** Spike, created 2024-04-11, updated 2025-04-14, no labels, no repository field, no parent, no links, no comments, status To Do. Description: "As a data analyst, I want to get all segment events." AC: "Implement something like this custom proxy or think of another solution."

## Claim

If this were done, the web apps would load Segment's analytics.js and send its events through a first-party host (a reverse proxy on our own domain), so ad blockers that drop `cdn.segment.com` and `api.segment.io` no longer cost the data analyst events. "Or think of another solution" leaves room for a different way to get the events that ad blockers drop.

## Evidence

- Segment is still loaded straight from Segment's CDN: `kasa-website` @ `b166a368`, `plugins/segment.js:112` and `guest-portal` @ `7cce37fb`, `plugins/analytics.js:152` both build `https://cdn.segment.com/analytics.js/v1/<key>/analytics.min.js`. No `apiHost` or `cdnURL` override found in any HSP repo. So the literal ask is not built.
- The "another solution" half has partly appeared: `HSP-4134` "Add PostHog alongside Segment" (Done, `kasa-website` `b50fce34`, 2026-09-28, #1927) initialises PostHog with `api_host` pointing at "our reverse proxy" (`kasa-website` `plugins/posthog.js:4,184,192`; `kasa-app` `apps/website/src/lib/analytics/posthog.ts:14,165`; also guest-portal, kontrol). The code comments say Segment "loads from `cdn.segment.com`, which ad blockers block; PostHog is served from our own domain and survives that". So the same traffic ad blockers hide from Segment now reaches PostHog. The Segment events themselves are still lost for those users.
- Sibling in the backlog: HSP-1594 "Implement Segment Custom Domain delegation for more reliable data collection" is the same need by another route, and is queued for review.
- Not checked: whether `POSTHOG_HOST` actually resolves to a reverse proxy in production (it is an environment value, not in the repos), and whether the data team has moved their reporting from Segment to PostHog.

Product question for Adam: does the data analyst still need every event in Segment, or is PostHog becoming the source for web analytics? If PostHog replaces Segment for this, this and HSP-1594 close as superseded. If Segment stays the warehouse feed, the proxy is still missing and both stay open.
