## Claim

If this ticket were done, the "Search listings" box at the top of the Multicalendar resource column would accept several unit
numbers separated by `,` or `;` and show every unit that matches any of them. What would make it moot: a different
multi-unit filter, or the old calendar being retired with the new one doing this.

## Evidence

- `kontrol` @ origin/master `cbf3f48d`, the live Vue Multicalendar (still changing, latest MC commit `18806f4e`, 2026-09-29):
  - `src/views/multi-calendar/MultiCalendar.vue:126-133` is the single `listingFilterInput` search box.
  - `src/store/modules/multicalendar/index.js:191-197` matches a unit when the whole filter string, minus dashes and spaces,
    is contained in the unit's internal title, with a 3-character minimum. No split on `,` or `;`.
  - `:147-152` matches room types with `new RegExp(listingFilter, 'i')`, so `a|b` happens to work for room types. Units do not get that.
  - The filter logic dates from 2021 (`d9832a5c`, TKON-124).
- `kontrol-ui` @ `ea34ed10e`, the React Multi-calendar v2 preview (`libs/kontrol-ui/pages/multi-calendar/`, added `937394a31`,
  2026-07-07, #2445, still receiving fixes through 2026-10-06): no listing search input at all. A grep for `placeholder`,
  `type="search"` and `listingFilter` under `src/` found nothing. Its filters are the view filter menu and sort/group menu.
- The location picker in `CalendarFilters.vue:20-45` is a multi-select, but over metros, cities, states and properties, not unit numbers.
- `git grep` for a split on `,` or `;` in the MC store and views finds only the route-query parsing for locations
  (`CalendarFilters.vue:485`).
