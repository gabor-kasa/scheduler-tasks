# HSP-1711: Spec a service to return various editing rules for sources

- **Verdict:** partial, product question
- **Label:** backlog-review-unclear
- **Confidence:** medium
- **Checked:** 2026-10-19, scheduled-task batch
- **Jira before write:** Spike, created 2024-10-24, updated 2025-11-18, no labels, no Repository field, status To Do, no parent, no links, no comments. Links a Notion spec "Separate booking source from booking behavior".

## Claim

Done means: a written spec (it is a Spike) for a service that returns, per booking source, which reservation fields can be edited and when, replacing the rules hardcoded in Kontrol. The must-have use case is the VFD cancel and modify request: show different copy to guests Kasa can handle versus guests who must go back to their booking platform. What would make it moot: a service that already returns these rules, or the VFD use case met another way.

## Evidence

- A neighbouring service exists but does not hold edit rules. `kasadev/booking-behavior` (active, last push 2026-10-07, not in `default-branches.tsv`) implements the Notion spec the ticket links. Its types (`types/src/booking-behavior.ts`, `channel-behavior.ts`) cover PAC requirements, payment timing, invoice rendering and `isCancelable` / `cancellationPolicy`. A grep for edit, modify and alter finds nothing about field editability. `kasadev/reservation-source-rules-service` is archived (last push 2026-02-26).
- The cancel half of the VFD use case is met another way. `guest-api` @ 5a79055b `service/src/components/booking/cancel/cancel.service.ts:28` asks kontrol-api for eligibility and gets `canCancel` and `cancellationDenialReasons`. `kontrol-api` @ 284f5864 `service/app/components/reservation-v2/reservation.controller.ts:1058` computes them. For corporate, group, combined, tenant or extension-chain reservations guest-api sends the request to Kustomer instead (`cancel.service.ts:72-82`). So a guest who cannot self-cancel is routed to support, without a source-rules service.
- The modify half is not built. HSP-1677 (modify booking in the VFD) has no endpoint on guest-api master. See `tickets/HSP-1677.md`.
- Kontrol editing rules: a search of kontrol-ui and kontrol-api for a shared edit-rules module found none, and I did not locate the hardcoded Airbnb room-type rule the ticket describes. So I cannot say whether it is still hardcoded or moved.
- Searched: kontrol-ui, kontrol-api, guest-api, add-on-service, and the booking-behavior repo through `gh api`.

## Note for review

Adam: this is a spike, so the question is whether the spec is still wanted. The cancel use case shipped through an eligibility endpoint, the generic "editing rules by source" service did not, and the booking-behavior work took the "source versus behavior" idea in a different direction (payments and PAC, not edits). If the modify request (HSP-1677) is dead, this spike has no must-have use case left and can close.
