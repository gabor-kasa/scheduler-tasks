# HSP-1294: Create earlyCheckInRequested event -> BW to auto tag rez

- **Verdict:** partial (the Breezeway tag exists, the "guest requested" event does not)
- **Label:** backlog-review-unclear
- **Confidence:** medium
- **Checked:** 2026-10-19, scheduled-task batch
- **Jira before write:** Story, created 2024-07-15, updated 2025-11-18, no labels, status To Do, no parent, no links. Repository field: breezeway-sync, kontrol-api, sns-events. One comment, Adam Kiss, 2024-12-09: "cuss if this is still needed (in this form) now that we released the new ECI functionality".

## Claim

Done means: a new `earlyCheckInRequested` SNS event in `sns-events`, published by `kontrol-api` when a guest requests early check-in, and consumed by `unified-sync-reservations-to-breezeway` to add ECI tags to the Breezeway reservation. What would make it moot: the tag already reaching Breezeway another way, or ECI no longer being a request/approve flow.

## Evidence

- The tag half exists. `breezeway-sync` @ ff025a86 `functions/unified-sync-reservations-to-breezeway.ts:309-313` adds `ECI_<hour>` when `earlyCheckIn.status === REQUESTED`. Added 2024-07-08 in 42d52b2 "HSP-896: add tags to reservations in Breezeway" (HSP-896, Done 2024-07-15), a week before this ticket was written.
- The subscription half exists, but on an older event. `breezeway-sync` `serverless.yml:793-800` subscribes the unified-sync queue to `reservationEarlyCheckinFifo` (switched to FIFO in 7c4eedd, 2024-09-10, HSP-1442). `sns-events` @ 93033a4a `src/publishers/reservation/reservationEarlyCheckinFifo.ts:5` defines `reservationEarlyCheckin`, in the repo since 2020 (7e04d07, "Early checkin event (#17)").
- The trigger the ticket asks for is missing. `kontrol-api` @ 284f5864 `service/app/components/reservation-v2/early-check-in/v2/reservation.early-check-in.service.ts:90-93` publishes `reservationEarlyCheckin` only when the new status is APPROVED or DENIED. The guest request path (`reservation.early-check-in.controller.ts:103`) sets REQUESTED and publishes nothing. No `earlyCheckInRequested` identifier exists in `sns-events`, `kontrol-api`, `guest-api` or `breezeway-sync` (only in generated GraphQL types, case-insensitive hit).
- Context shift: ECI is now an add-on. `add-on-service` publishes ordered and activated events and calls the same request/approve service (the comment at `reservation.early-check-in.controller.ts:82-83` says the two arrive about a second apart). For paid ECI the status passes through REQUESTED and then APPROVED within seconds. The approval publishes the event and Breezeway gets the earlier check-in time through `chooseCheckInTime` (`utils/common/index.ts`).
- Not checked: whether any other reservation-changed publish happens while status is REQUESTED (so the tag might be applied incidentally), and what Breezeway shows in production for ECI reservations. Prod data would settle it: count BW reservations with an `ECI_*` tag in the last 90 days.
