# HSP-224: Rotate basic auth in airbnb-sync

- **Verdict:** superseded (service shut down)
- **Label:** backlog-review-obsolete
- **Confidence:** medium-high
- **Checked:** 2026-10-15, scheduled-task batch
- **Jira before write:** created 2023-07-11, updated 2023-09-01, no labels, parent IN-482, status To Do

## Claim

If this ticket were done, a scheduled lambda would rotate the basic-auth credentials for the airbnb-sync management
endpoints, and the basic-auth authorizer would read them at runtime from Secrets Manager or Parameter Store instead of
deploy-time values. The alternative that makes it moot: airbnb-sync no longer runs.

## Evidence

- `airbnb-sync` (kasadev/airbnb-sync, archived on GitHub, not in `default-branches.tsv`, read through `gh api`) @ master `914153c19`:
  - Commit `cb74ac93e` "chore: shut down airbnb-sync (reservedConcurrency 0 on all functions)", merged 2026-06-16 as
    PR #202 (RC-3948). Its message says every function is disabled and stays down across deploys.
  - `serverless.yml:253-259` the `managementRouteAuth` function has `reservedConcurrency: 0 # disabled (service shutdown)`
    at line 255. The management routes it guarded cannot be called.
  - `serverless.yml:72-76` shows the credentials come from Secrets Manager through `${ssm:/aws/reference/secretsmanager/...}`
    (secret `credentials/airbnb-sync-management`). They are resolved at deploy time, which is what the ticket disliked, but the stack is off.
- Replacement: `airbnb-api` @ origin/master `6be5cd1`, `service/src/webhook/AirbnbWebhookBasicAuthCredentialsProvider.ts:21-40`
  reads webhook basic-auth credentials from Secrets Manager at runtime (not deploy-time). The management endpoints have no counterpart there.

## Note for review

Safe to close. No rotation lambda exists in airbnb-sync or airbnb-api, but the service the ticket targets is disabled.
Secrets check: no hardcoded credential found on airbnb-sync master or in the airbnb-api provider. Both refer to
Secrets Manager entries by name only, so there is nothing to flag for rotation from this review. The webhook basic-auth
secret used by airbnb-api is the same one the Airbnb partner-app credentials live in (per code comment), and has no
rotation job. Whether that needs one is a separate question for Security, not this ticket.
Gap in the task setup: `airbnb-sync` and `airbnb-api` are not in `default-branches.tsv`, so hsp-grep.sh cannot search them.
