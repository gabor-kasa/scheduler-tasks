## Claim

If this ticket were done, the guest portal address card would show and link to the building address when it
differs from the property address. The map link would not use lat/lng.

## Evidence

- `guest-portal` @ origin/master `f578d4d6`, `components/cii/dynamic/AddressBlock.vue` (script section): `mapLink`
  still prefers `address.lat`/`address.lon` for the Google Maps link, then falls back to the street query.
- `guest-api` @ origin/master `59277576`, `service/src/components/booking/helpers/transformer.booking-helpers.ts`:
  - `:115`: `address` is `unit.address`, falling back to the property address. This dates from 2021 (`c242faf8`), so it predates the ticket.
  - `:117`, `:177`: `guestFacingAddress` comes from the building's guest-facing addresses per unit. This was added by
    `7d4e0be8` (2026-03-23, HELP-11316, #2717).
- No frontend renders `guestFacingAddress`. A search of guest-portal and kasa-app found no hits.

## Note for review

The building-level address now exists in the booking API, but the address card does not show it, and the
map link still uses coordinates. What is left is frontend work. Is the WEL-style case still happening?
